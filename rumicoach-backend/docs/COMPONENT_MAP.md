# Component Map — rumicoach-backend

## Directory breakdown

| Path | What lives here |
|---|---|
| `api/openapi.yaml` | Source of truth for the REST API. Edit this first, then regenerate. |
| `api/types.gen.go`, `api/server.gen.go` | Generated by oapi-codegen v2.7.0 — never edit by hand. Regenerate with the exact commands in `CLAUDE.md`. |
| `api/routes/chat.go` | The one hand-written route: `GET /ws/chat` WebSocket endpoint + browser-origin checks + the `BALANCE_ENFORCED` minutes gate (402 before upgrade, minimum one minute). |
| `cmd/server/main.go` | Entry point: router construction, CORS, logging, **`selectiveAuth` path allowlist**, JWKS endpoint, Swagger. |
| `cmd/check_db/`, `cmd/check_sessions/`, `cmd/test_recommendations/` | Ad-hoc inspection/diagnostic CLIs. |
| `cmd/customer_simulator/`, `customer_simulator/` | Scripted fake-customer driver for exercising voice sessions end-to-end. |
| `config/config.go` | All configuration; env vars with dev-friendly defaults; production safety check for signing keys. |
| `database/db.go` | GORM connection, `AutoMigrate`, idempotent data backfills. |
| `internal/handlers/` | REST handlers, one file per resource (auth, user, action, growth, memory, streak, quote, recommendation, wheel_of_life, balance, timezone, admin, internal_api, channels, whatsapp_webhook). |
| `internal/models/` | GORM models (user, identity, communication_session, action, daily_growth, memory, streak, wheel_of_life, eisenhower_matrix, recommendation, notification, verification_code, balance_transaction, channel_binding, channel_message, channel_follow_up). |
| `internal/services/chat/` | **The voice engine.** `live_api.go` (ChatSession proxy + turn lifecycle), `tools.go` (tool dispatch), `system_prompt.go` (language rules), `registry.go`, `recommendation_agent.go`, `session_review.go`, `providers/` (Gemini transport). |
| `internal/services/chat/session/` | Session-type registry: `persona.go`, `session.go` + one package per session type (`onboarding/`, `checkin/`, `movement/`, `values/`, `energy/`, `decisions/`, `beliefs/`). Each owns prompts, tools, transitions. |
| `internal/services/messaging/` | Messaging-channel abstraction (`Channel` interface, registry, mock) + `whatsapp/` Meta Graph API client (send, media, webhook types, HMAC signature). Telegram would be a sibling package. |
| `internal/services/companion/` | **The WhatsApp conversation engine** (async STT + LLM + TTS over Gemini `generateContent`): `service.go` (turn orchestration, link codes), `prompt.go` (standalone messaging persona), `tools.go` (`save_memory`), `audio.go` (transcribe/TTS/ffmpeg), `dispatcher.go` (proactive follow-ups, ephemeral-history purge). See `docs/whatsapp-channel.md`. |
| `internal/services/balance/` | Minutes bank: atomic credit/debit of `users.balance_seconds` + the `balance_transactions` ledger. All balance writes go through here. |
| `internal/services/growth/` | Growth-journey sequencing (`deepSequence`, `ProposeSession`, `PlannedSessionForToday`). |
| `internal/services/notification/` | FCM push + scheduled push notifications. |
| `internal/services/quote/`, `internal/services/regional/` | Daily quotes; auth-plane ↔ data-plane routing/provisioning helpers. |
| `internal/templates/emails/` | Verification-email templates. |
| `internal/apierror/` | API error helpers. |
| `pkg/auth/` | JWT issue/verify (`jwt.go`), Cloud KMS signer, dev HS256 signer, JWKS handler, auth middleware, admin-role checks. |
| `docs/` | `sessions.md`, `control-markers.md`, `api-goals-tasks.md`, `google-sso-setup.md`, `whatsapp-channel.md`. |
| `test_logs/` | QA transcript logs (`[timestamp] [ROLE]` format) used to debug session behavior. |
| `Dockerfile`, `bitbucket-pipelines.yml` | Container build + CI (branch → environment: `development` → QA, `main` → prod). |
| `db-proxy_*.sh`, `cloud-sql-proxy` | Cloud SQL Auth Proxy tunnels to deployed DBs. |
| Repo root scratch (`read_db.go`, `test_regex.go`, `rumi.db`, `tmp*`, `scratch/`, `*.py`, `run_loop.sh`, …) | Uncommitted-quality scratch/debug artifacts. They contain duplicate `main()` functions — this is why `go build ./...` fails; build the real packages instead. |

## Critical / high-risk files

| File | Why it's risky |
|---|---|
| `cmd/server/main.go` — `selectiveAuth` | **Security boundary.** Hand-maintained auth allowlist; a forgotten prefix leaves a new route unauthenticated. Every new route must be considered here. |
| `pkg/auth/*` | Token signing/verification across planes; mistakes break login for every client, or worse, accept forged tokens. |
| `internal/services/chat/live_api.go` | The stateful heart of the product. Turn-lifecycle flags, per-user session registry, restart & resumption logic, disconnect housekeeping. Read `CLAUDE.md` before editing — several invariants are non-obvious (e.g. flags reset only in TURN_COMPLETE; nudges must not fire after `clientGone`). |
| `internal/services/chat/tools.go` | Tool dispatch + implicit state advancement. A tool declared but not handled (or vice versa) kills live sessions. |
| `internal/services/chat/session/*/` (prompts) | Prompts are runtime-translated templates; never add English phrase-matching against AI/user text. Persona is duplicated in `session/persona.go` and `onboarding/system_prompt.go` — edits must be mirrored. |
| `internal/services/balance/balance.go` | **Money-equivalent ledger.** `users.balance_seconds` must always equal the sum of `balance_transactions`; every write goes through `Credit`/`DebitSession` (row-locked transaction). Full-row user `Save`s elsewhere must `Omit("balance_seconds")`. |
| `database/db.go` | Runs migrations/backfills on startup against production data. Backfills must stay idempotent. |
| `internal/handlers/internal_api.go` | Server-to-server provisioning/deletion between planes, gated by service-account allowlist. |
| `internal/handlers/whatsapp_webhook.go` | **Security boundary.** Public endpoint (outside `/v1`) self-authenticated only by Meta's HMAC signature; also the dedupe gate against webhook redeliveries. |
| `internal/handlers/admin.go` | Admin + QA test-setup endpoints (`POST /v1/admin/test-setup` resets user fixtures, deliberately preserving `communication_sessions`). |
| `api/openapi.yaml` | Contract for all clients; breaking changes ripple into `rumicoach-app` and `rumicoach-backoffice`. |
